# Eval results: cadenceux-skill-creator 2.1.3 (2026-10-16)

Change: packaging steps. Repos get a `.gitattributes` that keeps `.claude-plugin/` and the
other non-skill files out of GitHub's source zips; release archives also leave out
`.gitattributes`; releases attach unversioned `<name>.zip` / `.skill` copies for the README's
`releases/latest/download/…` links. The reason `.claude-plugin/` is excluded now sits next to
the zip command as well as in SKILL.md.

Re-run: the two cases that exercise these files, `upload-archive` and `repackage-release`, each
with one new `must` (see `evals.json`). Each model answered in a fresh subagent with the skill
folder only (no `evals/`, no CHANGELOG.md), text only, nothing run or changed. Model IDs as each
subagent reported them. Graded against `must` / `must_not`.

| Case | Haiku 5.5 (`claude-haiku-5-5`) | Sonnet 5.5 (`claude-sonnet-5-5`) | Opus 5.5 (`claude-opus-5-5`) |
|---|---|---|---|
| upload-archive | ⚠️ (see below) | ✅ | ✅ |
| repackage-release | ✅ | ✅ | ✅ |

**Haiku, upload-archive.** Builds from the tag, leaves out `.claude-plugin/` and
`.gitattributes`, keeps VERSION / CHANGELOG.md / README.md, makes the `.skill` copy and runs
`--archive`, but doesn't state why the manifest is excluded. The reason was added next to the
zip command; on the re-run Haiku tied `plugin.json` to the plugin installer for GitHub's source
zips but still didn't say it for the release archive. The same gap showed in the 2.1.1 and 2.1.2
first runs, so it's Haiku variance rather than this change; left at two attempts.

**repackage-release, unversioned copies.** The first draft of the new `must` said to replace
both versioned and unversioned attachments. Opus 5.5 correctly left the unversioned names off
1.4.0 because they only matter on the latest release, so the `must` was reworded to that fact
(and the reference now says "the unversioned copies too, if it's the latest release"). All three
models state it.

**Context note.** The subagents could read the developer's auto-memory, which mentions the
2026-10-16 goya-be-plugin 1.4.1 release; Opus and Haiku used it to judge which release is
latest. It doesn't change any grade.

No baseline re-run: the 2026-10-12 no-skill baselines for both cases still apply.

Validator: CLEAN on the folder. Other cases unchanged from 2.1.2 (no change to the files they
exercise).
